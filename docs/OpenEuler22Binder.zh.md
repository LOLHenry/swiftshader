# 在 openEuler 22 上让内核提供 Android Binder

redroid 要靠宿主机内核提供 Binder（`/proc/filesystems` 里有 `nodev binder`）。没有 `systemctl start binder`。openEuler 22 的 Linux 5.10 默认不打开，也不能 `modprobe` 出一个发行版模块。

判断只看这一行，不要看宿主机有没有 `/dev/binder`：

```bash
uname -r
grep binder /proc/filesystems || echo "还没有 binder"
```

有 `nodev binder` 就停，去跑秒表环境。没有则换一颗打开了下面四项的 5.10 内核（[redroid 的 openEuler 说明](https://github.com/remote-android/redroid-doc/blob/master/deploy/openeuler.md)）：

```text
CONFIG_ANDROID=y
CONFIG_ANDROID_BINDER_IPC=y
CONFIG_ANDROID_BINDERFS=y
CONFIG_ANDROID_BINDER_DEVICES="binder,hwbinder,vndbinder"
```

ashmem 不是硬条件。秒表脚本已用 `androidboot.use_memfd=true`。

## 323 上已跑通的做法

对象：openEuler 22.03 SP4 aarch64，发行版内核 `5.10.0-323.0.0.224.oe2203sp4.aarch64`。新内核发布名必须是 `5.10.0-323.0.0.224.oe2203sp4-binder.aarch64`。在 `tmux` 里做，工作目录用 `/home`（约需 20G），不要在 `/usr/src` 里 `make`。

```bash
KNOW=5.10.0-323.0.0.224.oe2203sp4.aarch64
PKG=/usr/src/linux-${KNOW}
SRC=/home/linux-${KNOW}
OUT=/home/kbuild
OLD=/boot/vmlinuz-${KNOW}

# 1. 同一颗源码。yum reinstall 清不掉 make 残留。
yum remove -y kernel-source-${KNOW}
rm -rf "$PKG" "$SRC" "$OUT"
yum install -y kernel-source-${KNOW}
rpm --verify kernel-source-${KNOW}    # 应无输出
# Android Makefile 必须是 binder.o binder_alloc.o，不能是 binder_linux

# 2. 拷到 /home，版本号只加 -binder（不要变成 5.10.0-binder）
mkdir -p "$OUT" "$SRC"
rsync -a "$PKG/" "$SRC/" || cp -a "$PKG/." "$SRC/"
echo '-binder' > "$SRC/localversion"

# 3. 以正在跑的 323 配置为底，只开 Binder
cp -f /boot/config-${KNOW} "$OUT/.config"
"$SRC/scripts/config" --file "$OUT/.config" \
	--enable ANDROID --enable ANDROID_BINDER_IPC --enable ANDROID_BINDERFS \
	--set-str ANDROID_BINDER_DEVICES "binder,hwbinder,vndbinder" \
	--disable ANDROID_BINDER_IPC_SELFTEST --disable GCC_PLUGINS
command -v pahole >/dev/null || \
	"$SRC/scripts/config" --file "$OUT/.config" --disable DEBUG_INFO_BTF
make -C "$SRC" O="$OUT" olddefconfig
# 若仍问 GCC_PLUGINS (NEW)，答 n

# 4. 源码包不带发行版签名私钥，本地现编一颗
mkdir -p "$OUT/certs" "$SRC/certs"
printf '%s\n' \
	'[ req ]' 'default_bits = 4096' 'distinguished_name = req_distinguished_name' \
	'prompt = no' 'string_mask = utf8only' 'x509_extensions = myexts' '' \
	'[ req_distinguished_name ]' 'CN = Build time autogenerated kernel key' '' \
	'[ myexts ]' 'basicConstraints=critical,CA:FALSE' \
	'keyUsage=digitalSignature' 'subjectKeyIdentifier=hash' \
	'authorityKeyIdentifier=keyid' > "$OUT/certs/x509.genkey"
\cp -f "$OUT/certs/x509.genkey" "$SRC/certs/x509.genkey"
openssl req -new -nodes -utf8 -sha256 -days 36500 -batch -x509 \
	-config "$OUT/certs/x509.genkey" -outform PEM \
	-out "$OUT/certs/signing_key.pem" -keyout "$OUT/certs/signing_key.pem"

# 5. 编译。发布名必须带 323 和 binder。
make -C "$SRC" O="$OUT" -j64 Image modules
KREL=$(cat "$OUT/include/config/kernel.release")   # 期望 …323…-binder.aarch64

# 6. 安装。vmlinuz 必须是 gzip 的 Image；默认启动仍指 323
make -C "$SRC" O="$OUT" modules_install
gzip -9 -c "$OUT/arch/arm64/boot/Image" > /boot/vmlinuz-"$KREL"
chmod 755 /boot/vmlinuz-"$KREL"
dracut -f --kver "$KREL" /boot/initramfs-"$KREL".img
grubby --add-kernel=/boot/vmlinuz-"$KREL" \
	--title="openEuler ${KREL} (binder gzip)" \
	--initrd=/boot/initramfs-"$KREL".img --copy-default
grubby --set-default "$OLD"
```

`file /boot/vmlinuz-$KREL` 应是 `gzip compressed data, was "Image"`。`uname -r` 和默认启动此时仍是 323。

打开 iBMC 能看见 GRUB 后再切过去：

```bash
grubby --set-default /boot/vmlinuz-5.10.0-323.0.0.224.oe2203sp4-binder.aarch64
reboot
```

进来后期望 `uname -r` 为 `…323…-binder.aarch64`，且 `grep binder /proc/filesystems` 有 `nodev binder`。失败在 GRUB 选回 323，再 `grubby --set-default $OLD`。

仓库脚本（离线、不改默认启动）：`scripts/redroid_4u8g_stopwatch/build_binder_kernel.sh`。

## 之后

测试机上 redroid 仍起不来时先 `setenforce 0`。鲲鹏用 `*_64only` 镜像。然后按 [Stopwatch4U8GEnvironment.zh.md](Stopwatch4U8GEnvironment.zh.md) 跑 `scripts/redroid_4u8g_stopwatch/run.sh`。

不要做：在 `/usr/src` 里 `make`；把未压缩 `Image` 当 `vmlinuz`；发布名写成 `5.10.0-binder`；用 `*binder*` 一把删启动项（会删掉已成功的 323-binder）；编 4.19 / redroid-modules；把没有 `/dev/binder` 当成失败。树外 `binder_linux.ko` 在这颗 5.10 上会卡在未导出符号，现场已放弃。
