采样例程
========

[English](SamplingRoutines.md) | 中文

简介
----

与其他现代实时图形 API 一样，Vulkan 支持[采样器对象](https://www.khronos.org/registry/vulkan/specs/1.2/html/vkspec.html#samplers)，它们提供着色器中图像读取和采样指令所使用的采样状态。[采样器描述符](https://www.khronos.org/registry/vulkan/specs/1.2/html/vkspec.html#descriptorsets-sampler)包含或引用该状态。采样器描述符会与图像描述符[组合](https://www.khronos.org/registry/spir-v/specs/unified1/SPIRV.html#OpSampledImage)，而这种组合可能直到着色器执行时才知道。

这对 SwiftShader 使用的[动态代码生成](Reactor.zh.md)提出了挑战：我们希望针对图像属性（最主要的是格式）和采样器状态来特化采样代码。历史上，采样器状态要么是纹理对象的一部分，要么纹理对象和采样器对象都会在着色器执行之前绑定到纹理单元。

JIT 蹦床（Trampoline）
----------------------

解决方案是把采样指令的代码生成推迟到着色器执行时。对于每个图像采样操作，我们生成对一个 C++ 函数的调用；该函数会根据运行时使用的图像描述符和采样器描述符提供特化后的例程。然后我们调用返回的例程。

注意，这与典型 JIT 编译器使用蹦床函数的方式不同：我们会针对状态组合生成专用代码，并在状态变化时动态适配。

三级缓存
--------

我们会缓存生成的采样例程，以描述符以及采样指令类型作为键。缓存分为三级，为便于理解按相反顺序说明：

L3：第三级也是最后一级，使用通用的最近最少使用（LRU）缓存，与管线各阶段例程的缓存相同。它由互斥锁保护，由于所有着色器工作线程都需要采样例程，该锁可能争用激烈。

L2：为缓解这一问题，有二级缓存，其中保存最后一级缓存的“快照”，可以无锁地并发查询。快照在管线屏障处更新。虽然比最后一级缓存的临界区快得多，但每次采样指令仍要做一次哈希表查找，开销仍然不小。

L1：采样指令多次执行之间，所用描述符常常不变。这就是第一级或“[内联](https://en.wikipedia.org/wiki/Inline_caching)”缓存发挥作用的地方。它是在已编译的采样指令级别实现的单条目缓存。在调用 C++ 函数获取例程之前，我们会检查自该指令上次执行以来，采样器描述符和图像描述符是否未发生变化。注意该缓存不以指令类型作为查找键的一部分，因为每个采样指令实例都有自己的内联缓存。

描述符标识符
------------

为了快速判断描述符状态是否保持不变，它们具有唯一的 32 位标识符。注意，与采样例程特化相关的采样器对象状态和图像视图状态，在采样器对象和图像视图对象之间未必唯一。对于图像视图，我们能够把状态压缩进 32 位标识符本身，以避免不必要的重新编译。

对于采样器状态（远大于 32 位），我们维护一份从该状态到唯一标识符的映射。我们会计数有多少采样器对象共享每个标识符，以便知道何时可以移除该条目。

这两个 32 位标识符是第一级采样例程缓存所用的全部键。
