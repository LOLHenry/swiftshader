从应用渲染循环到上屏：Worker 在哪

redroid guest + vulkan.pastel.so · 普通应用走 HWUI / Vulkan 这一路

一帧里 Worker 只出现两次：应用自己的 pastel 线程池画应用的像素，SurfaceFlinger 自己的 pastel 线程池做合成。中间提交命令、排队、拷到 AHardwareBuffer、上屏，都不是 Worker 做的。

一整帧

显示 / Choreographer
1. Vsync 到了
系统按目标帧率（如 30）发垂直同步。应用主线程被叫醒，开始这一帧。
▼
应用 UI 线程
2. 改界面、记显示列表（DisplayList）
应用改 View（文字、布局、可见性），再 invalidate。UI 线程只把「这一帧画什么」记成一份操作清单，还不是像素。真正画图不在这条线程，交给 RenderThread。
▼
应用 RenderThread + HWUI / Skia
3. 把显示列表变成 Vulkan 命令
GLES 会先经 ANGLE 再进 pastel；Vulkan 直接进 pastel。这里是 vkCmdDraw 等，只往命令缓冲里记，几乎不算像素。
▼
应用 Vulkan Queue 线程（Queue<…>）
4. vkQueueSubmit：命令真正开始执行
Queue::submit 把任务丢进内部队列；taskLoop 里 bind() 调度器后逐条执行命令缓冲。这条线程不是 Thread<NN>。
▼
SwiftShader Renderer
5. Renderer::draw：为这次绘制准备 Routine
按管线状态找或现场 JIT：VertexRoutine、SetupRoutine、PixelRoutine、sampler。第一次会编，之后复用。
▼
应用 Worker · marl::schedule
6. 切成 batch，丢进线程池 —— Worker 从这里开始干活
DrawCall::run 按最多约 128 个图元一块 marl::schedule。哪条 Worker 空谁拿。
▼
同一条应用 Worker 上顺序做完一块
7. 顶点 → 图元 → 像素
processVertices 跑顶点 JIT；processPrimitives 裁剪、装配、边方程； processPixels 四像素一组光栅化 + 片元 + 采样 + 写颜色/深度。 perf 里的 PixelRoutine / sampler 主要在这。
▼
应用进程 · CPU 上的 vk::Image
8. 这一帧的颜色已经在内存里
没有 GPU framebuffer。Queue 在 fence 前会 renderer->synchronize()，等所有 batch 做完。
▼
应用 · Android 图像导出
9. 拷到 AHardwareBuffer，交给 BufferQueue
vkQueueSignalReleaseImageANDROID → 按行 memcpy 到 AHB（memfd）。 然后 queueBuffer 给 SurfaceFlinger。这一步常是 memcpy 热点，不是 Worker 空转。
▼
SurfaceFlinger 主线程
10. 合成这一屏：各层排在哪
读应用刚交来的 buffer，加上状态栏、壁纸等。能走 HWC 直通就少算像素；走 Client 合成就要再画一遍。
▼
SF 的 pastel（另一份 ICD）
11. SF 自己的 vkQueueSubmit，准备 Routine
对应应用侧的 4、5，不是 4→7。Client 合成时 SF 进程另加载一份 vulkan.pastel.so：Queue::submit，Renderer 找或 JIT 合成用的 Routine。ini、ThreadCount 各算各的。这里还没轮到 Worker 算像素。
▼
SF Worker · Thread<NN>
12. 采样各层、做片元、写出合成结果
对应应用侧的 6、7：SF 自己那套 Worker 把合成 draw 切成 batch。Client 合成时这一步经常比应用侧更热：全屏图层、逐像素采样。
▼
显示 / redroid
13. 上屏
合成结果进 framebuffer / 虚拟屏。scrcpy 另走一条编码，不是这条 pastel Worker。

一块 batch 在 Worker 里怎么跑

DrawCall::run
  marl::schedule(batch)     ← 入队，哪条空闲 Worker 领走
    processVertices         ← VertexRoutine JIT
    processPrimitives       ← SetupRoutine
    processPixels           ← PixelRoutine + sampler，写 vk::Image
有活被挡住：suspend，切到另一条纤程（Fiber），同一条 OS 线程继续干别的

没活时：spinForWork 空转

CPU 执行空指令 nop，人还占着核，并没有在算像素。目的是下一小块马上到时，免去把线程交给 OS 再唤醒。

刚做完
队列空
→
nop×256 空转
核约 100%，没算像素
→
看 work.num
或偷别人的活
→
有活：马上干
退出空转

没活且未满 1 ms：yield 一下，回到 nop 继续转

满 1 ms 仍没活 → wait() 睡觉（核约 0%）

  • 怎么转：一串 nop 占着核，隔一会儿看 work.num，没有就尝试从别的 Worker 偷任务。
  • 何时退出：自己队列来活、偷到活，或空转满 1 ms。
  • 意义：生产者刚做完又会丢下一批小任务。若一没活就睡觉，再被 OS 叫醒往往比 1 ms 还慢，整条流水线会顿一下。
